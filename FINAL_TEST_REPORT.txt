RAKAN SHOP - FEATURE UPDATE HANDOVER REPORT
Date: 16 November 2026

IMPLEMENTED IN THIS ARCHIVE
1. Image upload pipeline
   - Frontend validation: JPG/JPEG, PNG, WebP; original file maximum 4 MB; minimum dimensions 300 x 300.
   - Browser compression and WebP conversion using browser-image-compression (target 500 KB, maximum dimension 1600 px).
   - Backend multipart limit 4 MB and Sharp processing/validation; output is WebP, maximum dimension 1200 px, quality 87.
   - Applies to product and category image forms.

2. Backend discount pricing
   - Product API now returns originalPrice and discountedPrice.
   - discountedPrice is calculated by the API from the stored price and discount percentage.
   - Product cards display the discounted amount and strike through the original amount.
   - Checkout continues to calculate the final order price on the server.

3. Product archive
   - Added Product.isArchived.
   - Admin product page has Active products and Archived products views, with archive and restore actions.
   - Public product lists and search suggestions exclude archived products.
   - Checkout rejects archived products already left in a customer's cart.
   - Products are not hard-deleted, so old order item snapshots and order history remain intact.

4. Admin navigation
   - Sidebar order is Dashboard, Orders, Products, Categories, Delivery, Users.

5. Notifications
   - Added persistent database notifications for new orders (admin) and order status changes/cancellations (customer).
   - Added authenticated notification list/read/read-all endpoints and notification dropdowns.
   - Replaced 10-second polling with Supabase Postgres Changes subscriptions on public."Notification".
   - Added short-lived, server-minted Supabase Realtime JWTs based on the authenticated Rakan admin/customer session.
   - Added a SQL setup script with audience/customer-scoped RLS and Realtime publication membership.
   - On initial load/reconnect and each INSERT event, the UI reloads the persistent feed through the authenticated API, so offline notifications are not lost.

VALIDATION COMPLETED
- All API JavaScript files passed node --check.
- ZIP archive integrity passed unzip -t.
- Source inspection confirmed public product list/search filtering, archive/restore endpoints, order rejection for archived products, and transactional notification creation.

NOT COMPLETED / NOT CERTIFIED
- Full frontend production build was not completed because dependencies could not be downloaded in this environment. The frontend TypeScript command therefore reports missing installed modules, not a valid build result.
- Sharp and browser-image-compression are declared in package.json. The frontend now also declares @supabase/supabase-js; run npm install in frontend/ to install it and update package-lock.json before building/deploying.
- Prisma schema was updated but was not applied to the live Supabase database. Back up the database, then run npx prisma db push from api/.
- Live Supabase Storage image upload, real checkout, Supabase Realtime delivery, Arabic visual rendering, and Vercel deployment were not tested against the project's live environment.
- Realtime requires the one-time SQL in api/prisma/enable-notification-realtime.sql, SUPABASE_JWT_SECRET in the API environment, and VITE_SUPABASE_URL plus VITE_SUPABASE_PUBLISHABLE_KEY in the frontend environment. Follow REALTIME-NOTIFICATIONS-SETUP.md before expecting live events.
- The Realtime token exchange uses the project's legacy HS256 JWT signing secret. If the Supabase project uses only asymmetric signing keys and has no legacy JWT secret, this token-signing integration must be adapted before deployment.

HANDOVER STATUS
This is an implementation/testing candidate, not a production-certified release. Install dependencies, apply the Prisma schema, build both applications, and run live integration/browser tests before client production handover.
